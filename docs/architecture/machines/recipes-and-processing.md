# Рецепты, операции и атомарный жизненный цикл

Ключевые ADR: [007](decisions/AS-MACHINE-007.md), [008](decisions/AS-MACHINE-008.md), [010](decisions/AS-MACHINE-010.md), [012](decisions/AS-MACHINE-012.md), [013](decisions/AS-MACHINE-013.md).

## Выбранный рецепт vs активная операция

- **Выбранный рецепт** — пожелание/конфигурация для *следующих* запусков. Источник выбора (GUI, чертёж и т. п.) определяется машиной.
- **Активная операция** — уже начавшееся производство: собственный прогресс и неизменные существенные параметры. На неё **не влияет** последующее изменение выбранного рецепта.

## Логическая машина состояний

```text
IDLE / WAITING_FOR_INPUT
   │ полный расходуемый набор, условия запуска
   ▼
START (единая атомарная операция: списание + создание operation)
   │
   ▼
PROCESSING  ── нет энергии/условий ──> PAUSED
   ▲                                      │
   └──────────── условия вернулись ────────┘
   │ достигли 100%
   ▼
WAITING_FOR_OUTPUT  ── все продукты помещены атомарно ──> COMPLETED
   │ нет места хотя бы для одного продукта                  │
   └──────────────── ждём без потери/производства ──────────┘
                                                         ▼
                                                       IDLE
```

Названия — концептуальные, **не зафиксированный Java enum**.

## Запуск

1. Установить конкретный рецепт/условия для этой камеры.
2. Проверить полноту **всех** расходуемых ингредиентов: предметы, жидкости и газы; проверить нерасходуемые предметы по правилам рецепта.
3. Транзакционно проверить все требования и списать их как **одно целое**.
4. В той же логической атомарной границе зафиксировать создание активной операции.
5. При любом отказе итоговый результат: ни одного списания и ни одной новой операции.

Не создавать операцию, которую нельзя восстановить после сохранения/загрузки.

## Обработка

- Результаты/длительность, влияющие на эту операцию, фиксируются при старте и не пересчитываются из нового чертежа.
- При нехватке FE прогресс приостанавливается; оплаченный рабочий такт только целиком ([AS-MACHINE-011](decisions/AS-MACHINE-011.md)).
- Ожидание результата при 100% **не расходует** энергию и не запускает новую операцию этой камеры.

## Выдача набора результатов

**Набор результатов неделим.** Представим:
- предмет: очищенный металл ×2;
- жидкость: реагент;
- газ: побочный газ.

Если для предмета и жидкости место есть, а газовый бак полон, **ни один** результат не переносится из операции во внутренние выходные хранилища. Готовый набор хранится внутри состояния операции. После освобождения места все записи подтверждаются атомарно; операция закрывается один раз.

Извлечение продукции сторонними трубами **после** записи в выходные хранилища может быть обычным независимым выводом по соответствующим маршрутам.

## Многокамерные машины

Независимые камеры имеют независимые операции и прогресс. Несколько модулей могут также сотрудничать в рамках *одной* операции. Состояние ожидания выхода одной камеры не блокирует другую, если у той есть ингредиенты, FE и место.

**Атомарность ограничена операцией**, не всем заводом.

## Изменение рецепта

- Текущая операция всегда сохраняет собственный рецепт и выполняется до завершения, пусть и с паузами.
- Для будущих операций действуют новые требования.
- Несовместимые остатки входных хранилищ остаются у игрока либо возвращаются механизмом согласно [AS-MACHINE-019](decisions/AS-MACHINE-019.md).
- Новый рецепт не может стереть уже ожидающий набор результатов старой операции.

## Требует отдельной проработки

Формат снимка операции, детерминированные/случайные результаты, операции с нерасходуемыми инструментами, ресурсный rollback при краше и планирование очередности конкурирующих завершений в общий выход.
