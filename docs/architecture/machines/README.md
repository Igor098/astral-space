# Astral Space — архитектура машин и ресурсных систем

> **Статус документации:** утверждённая архитектура и актуальная фиксация реализованных FE/Fluid-компонентов и генераторов Coal/Lava в `main`; остальные ресурсные системы проектируются поэтапно.  
> **Базовая платформа:** Minecraft 1.21.11 / NeoForge 21.11.45 / Java 21.  
> **Первоначальная фиксация:** 2026-11-01; FE и визуализация: 2026-11-05; порты/жидкости: 2026-11-08; генераторы, потребители, накопители и мультиблоки: 2026-11-24.  
> **Язык:** русский.  
> **Внимание:** утверждённые ADR — правила проектирования, а не свидетельство завершения всех функциональных возможностей. Статус уже написанного FE-кода отдельно отмечен в [energy-system.md](energy-system.md).

## Назначение

Сформировать единый источник истины для дальнейшего развития генераторов, накопителей, электрических печей, промышленных машин и мультиблоков Astral Space. В FE-инфраструктуре реализованы `EnergyComponent` (хранилище), `EnergyTransferCoordinator`, `EnergyTransferBudget`, `EnergyPortHandler`, `EnergyPushTransfer`, `EnergyPortId`, политики, конфигурация и `EnergyDistributionManager` (адаптивное распределение). При этом **полная реализация машинных ADR и универсальная интеграция FE-портов ещё не завершены**. Синхронизация документации сама по себе production-код не изменяет.

## Энергетические ADR

- **[ADR-ENERGY-001/002 и TECH-DEBT-ENERGY-001](../energy/AstralSpace_Energy_Architecture_Decisions.md)** — канонический документ; перенос `EnergyDistributionManager` на `EnergyPortId` завершён в `main`.
- **[Энергетическая подсистема](energy-system.md)** различает реализованные классы и ещё не выполненную интеграцию. `EnergyComponent` — внутреннее FE-хранилище. Существующий Coal в `main` использует `EnergyTransferCoordinator` и пять флагов `BlockState.OUTPUT_*`; Lava Generator в `main` уже использует BE-owned `EnergyPortConfiguration` и динамическую модель. Целевая архитектура выделяет независимые Input/Output-контроллеры и диспетчер ([AS-MACHINE-023](decisions/AS-MACHINE-023.md), [AS-MACHINE-027](decisions/AS-MACHINE-027.md)); эти классы ещё не реализованы.
- **[Жидкостная подсистема](fluid-system.md)**: хранилища, политики, маршруты и обработчики Fluid уже интегрированы в Lava Generator в `main` (PR #3, `3216128`); собственные транспортные сети и общая архитектура производственных машин остаются целевыми задачами.
- Для последней локально проверенной версии распределителя прошли **66/66** целевых регрессионных тестов. Результат 66/66 относится к ранее проверенному набору тестов и не утверждает нового прогона после миграции Coal Generator Mk I (коммит `3c1ddff`).

### Статусы
- **Утверждено** — правило явно согласовано и подлежит соблюдению при реализации.
- **Открытый вопрос** — ещё нет окончательного решения; не выдавать предположения за требование.
- **Технический долг** — существующее поведение/код надо планово привести к целевой модели без потери проверенной логики.

## Принципы, важные для всей документации

1. Машина определяет, **что разрешено**, игрок — **на каких из разрешённых граней это включить**. На каждой грани для каждого типа выбран **только один** режим.
2. Не смешивать физическую грань, тип ресурса, логический маршрут и внутреннее хранилище.
3. Ресурсы не исчезают и не дублируются из-за автоматизации, смены рецепта или сбоя транзакции.
4. Результаты **одной операции** атомарны; разные операции могут быть независимы.
5. Не навязывать одну модель рецептов/инвентаря/камер всем типам машин.
6. Композиция предпочтительнее преждевременно разрастающейся иерархии `BlockEntity`.
7. Согласованные 28 ADR не означают 28 классов: существующие FE-классы учитываем, остальные модели Java вводим по мере подтверждения потребностей.
8. Совместимость со старыми сохранениями **не требуется**: мод пока не выпущен; допускается создание нового мира без миграций.

## Визуальные модели и составные коммуникации — решение 2026-11-05

- [AS-MACHINE-021](decisions/AS-MACHINE-021.md) теперь опирается на **локально проверенный** `VisualTestBlock`: серверная маска, синхронизация, `ModelData`, выбор запечённых частей и поворот по `FACING`. Код прототипа **не считается опубликованным в `main`**. Подробности и оставшиеся проверки: [visual-model-prototype.md](visual-model-prototype.md).
- [AS-MACHINE-022](decisions/AS-MACHINE-022.md) вводит **составной транспорт наших проводов/труб в одной клетке**. Сечения для 1, 2, 4, 5 коммуникаций согласованы; сечение трёх и геометрия поворотов ещё открыты. Обёртка у машины возникает автоматически. [Полная концепция](conduit-system.md).
- Сторонним AE2/Pipez-подобным системам не нужно разделять блок с нашими коммуникациями. Машины предоставляют стандартные capabilities на любой разрешённой стороне и одинаково соблюдают правила доступа.
- Для мультиблоков сохраняются отдельные специализированные хэтчи. Производственный Coal Generator Mk I не меняется до отдельной миграции.

Это **разные стадии готовности**: экспериментальный рендерер проверен в игре, динамический подход используется в Lava Generator в `main`, миграция Coal предстоит; составной транспорт пока только спроектирован.
## Актуальные правила после 2026-11-08

- На одной грани могут присутствовать разные ресурсы, но нельзя одновременно включить INPUT + OUTPUT **одного** типа. SERVICE допустим лишь для ITEM/FLUID/GAS при поддержке конструкцией; для FE действуют только INPUT/OUTPUT/DISABLED.
- Собственные предметные и жидкостные трубы имеют отдельное направление подключения («Подача в блок», «Забор из блока», «Оба направления» по умолчанию) и необязательный фильтр.
- Каждая жидкостная сеть переносит только один тип жидкости одновременно и **автоматически освобождает тип после полного опустошения** и завершения передач.
- Устаревшие правила исправлены **в существующих ADR**; отдельный заменяющий ADR не нужен, история правок доступна в Git.

## Решения о генераторах и мультиблоках от 2026-11-24

Новые [AS-MACHINE-023](decisions/AS-MACHINE-023.md)–[AS-MACHINE-027](decisions/AS-MACHINE-027.md) систематизируют согласованную архитектуру без дублирования решений: независимые FE-контроллеры, единую генераторную последовательность, Strategy и транзакционный топливный цикл, отдельные правила/топологию портов, а также идентичность и fail-closed физического мультиблока. Потребители и накопители FE используют отдельные контроллеры с одним буфером и без фиктивных зависимостей. В [energy-system.md](energy-system.md), [machine-architecture.md](machine-architecture.md), [persistence-and-networking.md](persistence-and-networking.md), [resource-connections.md](resource-connections.md), [implementation-plan.md](implementation-plan.md) и [open-questions.md](open-questions.md) отражены последствия этих решений.

**Архитектурные изменения 2026-11-24 — документационные.** PR дополнительно содержит лицензии, корневой README и сборочные настройки метаданных/упаковки лицензий; Java-код и игровые ресурсы не затронуты. Coal/Lava уже работают в `main`; их миграция на новые базовые BlockEntity, `FuelCycleComponent` и FE-контроллеры ещё предстоит. Lava Generator выступает ориентиром динамической визуализации. Существующие ADR 001–022 сохранены без дублирования. При последующих уточнениях применяется явно обозначенная область действия актуальных ADR: AS-MACHINE-024 уточняет AS-MACHINE-003 в части FIXED/CONFIGURABLE; AS-MACHINE-027 сохраняет обязательный Push накопителей из AS-MACHINE-003 и описывает его реализацию через независимый OUTPUT-контур.
