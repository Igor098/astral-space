# Astral Space — архитектура машин и ресурсных систем

> **Статус документации:** утверждённая архитектура и актуальная фиксация реализованных FE-компонентов; остальные ресурсные системы проектируются поэтапно.  
> **Базовая платформа:** Minecraft 1.21.11 / NeoForge 1.21.11 / Java 21.  
> **Первоначальная фиксация:** 2026-11-01; актуализация FE и визуализации: 2026-11-05.  
> **Язык:** русский.  
> **Внимание:** утверждённые ADR — правила проектирования, а не свидетельство завершения всех 20 функций. Статус уже написанного FE-кода отдельно отмечен в [energy-system.md](energy-system.md).

## Назначение

Сформировать единый источник истины для дальнейшего развития генераторов, накопителей, электрических печей, промышленных машин и мультиблоков Astral Space. В FE-инфраструктуре реализованы `EnergyComponent` (хранилище), `EnergyTransferCoordinator`, `EnergyTransferBudget`, `EnergyPortHandler`, `EnergyPushTransfer`, `EnergyPortId`, политики, конфигурация и `EnergyDistributionManager` (адаптивное распределение). При этом **реализация всех 20 машинных ADR и универсальная интеграция FE-портов ещё не завершены**. Синхронизация документации сама по себе production-код не изменяет.

## Энергетические ADR

- **[ADR-ENERGY-001/002 и TECH-DEBT-ENERGY-001](../energy/AstralSpace_Energy_Architecture_Decisions.md)** — канонический документ; перенос `EnergyDistributionManager` на `EnergyPortId` завершён в текущей локальной версии.
- **[Энергетическая подсистема](energy-system.md)** различает реализованные классы и ещё не выполненную интеграцию. `EnergyComponent` остаётся внутренним FE-хранилищем, а координация выполняется отдельным `EnergyTransferCoordinator`; источник режимов пяти выходов генератора пока находится в `BlockState`.
- Для последней локально проверенной версии распределителя прошли **66/66** целевых регрессионных тестов. Результат 66/66 относится к ранее проверенному набору тестов и не утверждает нового прогона после миграции Coal Generator Mk I (коммит `3c1ddff`).

### Статусы
- **Утверждено** — правило явно согласовано и подлежит соблюдению при реализации.
- **Открытый вопрос** — ещё нет окончательного решения; не выдавать предположения за требование.
- **Технический долг** — существующее поведение/код надо планово привести к целевой модели без потери проверенной логики.

## Принципы, важные для всей документации

1. Машина определяет, **что разрешено**, игрок — **на каких из разрешённых граней это включить**.
2. Не смешивать физическую грань, тип ресурса, логический маршрут и внутреннее хранилище.
3. Ресурсы не исчезают и не дублируются из-за автоматизации, смены рецепта или сбоя транзакции.
4. Результаты **одной операции** атомарны; разные операции могут быть независимы.
5. Не навязывать одну модель рецептов/инвентаря/камер всем типам машин.
6. Композиция предпочтительнее преждевременно разрастающейся иерархии `BlockEntity`.
7. Согласованные 21 ADR не означают 21 класс: существующие FE-классы учитываем, остальные модели Java вводим по мере подтверждения потребностей.
8. Совместимость со старыми сохранениями **не требуется**: мод пока не выпущен; допускается создание нового мира без миграций.
