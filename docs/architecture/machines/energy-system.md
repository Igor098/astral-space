# Энергетическая подсистема (FE)

Связано с [AS-MACHINE-003](decisions/AS-MACHINE-003.md), [AS-MACHINE-011](decisions/AS-MACHINE-011.md) и ранее согласованными `ADR-ENERGY-001/002` (см. [исходный документ](energy-existing-decisions.md)).

## Существующее рабочее состояние

Согласованные и уже реализованные части системы (состояние на момент обсуждения):

| Компонент | Смысл |
|---|---|
| `EnergyComponent` | Состояние и атомарные операции энергетического буфера |
| `EnergyPortId` | Логическая идентичность порта |
| `EnergyPortMode` | `INPUT`, `OUTPUT`, `DISABLED` |
| `EnergyPortPolicy` | Проверки разрешённости/доступности/изменяемости |
| `FixedEnergyPortPolicy` | Фиксированные правила |
| `ConfigurableEnergyPortPolicy` | Допустимые режимы и динамические проверки |
| `EnergyPortConfiguration` | Текущие режимы и уведомления |
| `EnergyPortConfigurationSerializer` | Чтение/запись состояния режимов |

Ранее для этих восьми частей было **125 проходящих тестов**; перед интеграцией заново проверить актуальный прогон, а не принимать это число за неизменное.

## Инварианты

- FE INPUT разрешает только внесение, FE OUTPUT — только извлечение, DISABLED — ни то ни другое.
- `BOTH` **не используем**.
- Производитель/накопитель инициирует Push через активный OUTPUT; внешняя кабельная система может сама делать Pull.
- Один и тот же FE нельзя дважды потратить через одновременные Push и Pull. Суммарный лимит FE/t обязателен.
- Проверки конфигурации динамические: старый объект capability не получает постоянных прав после выключения порта.
- Распределение между независимыми портами не должно зависеть только от `Direction`.

## Coal Generator Mk I — существующая логика, которую сохраняем

- Буфер: **10 000 FE**.
- Генерация: **40 FE/t**.
- Суммарный предел извлечения: **80 FE/t**.
- Потенциальные стороны выдачи: `BACK` (по умолчанию OUTPUT), `LEFT`, `RIGHT`, `TOP`, `BOTTOM` (по умолчанию отключены); `FRONT` не предоставляет энергетический канал.
- Пять `BlockState`-флагов вывода сейчас управляют визуальным отображением коннекторов; целевое решение: **конфигурация в BlockEntity — источник истины, BlockState — производная визуальная проекция**.
- Текущие `EnergyDistributionManager`, `EnergyExtractionBudget`, `EnergyTransferTracker` и обработчик выходной энергии содержат рабочую и протестированную логику Push/Pull и справедливости. Рефакторить только с защитными регрессиями.

## Обязательный технический долг

`EnergyDistributionManager` исторически использует `Direction` для идентичности получателя. Цель — `EnergyPortId`, включая `fairnessCredits`, статистику спроса/активности и лимиты. Тестировать случай двух независимых портов с одним `Direction` в мультиблоке.

## Внутри многокамерной машины

`AS-MACHINE-011`: общий буфер обслуживает рабочие такты камер по Round Robin. Каждый рабочий шаг либо целиком оплачивается, либо не выполняется; недостаток FE не уничтожает операцию. Камера с результатом, ожидающим место, FE не расходует.

## Не утверждено

- Конкретные Java-интерфейсы нового `EnergyPortHandler`, размер бюджетов разных машин, детали влияния апгрейдов.
- Конкретная формула «справедливых кредитов» при переходе `Direction → EnergyPortId`.
- Правила поведения специальных машин с активным энергетическим Pull.
