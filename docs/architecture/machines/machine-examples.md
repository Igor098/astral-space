# Эталонные сценарии машин

Каждый сценарий показывает **утверждённое поведение**. Это не обещание, что такая машина уже существует в коде.

## Сценарий A: Электропечь с одним слотом ресурса

```text
INPUT сверху  ──┐
                ├──> INPUT SLOT (сырьё) ──> операция ──> OUTPUT SLOT (результат) ──> OUTPUT справа
INPUT слева   ──┘
Energy INPUT (другая разрешённая грань)
```

### Случай A1 — один тип из нескольких сундуков

Сундук A отдаёт железную руду максимум 2/цикл, B — максимум 3/цикл, C содержит золото. Если активным стало железо, печь
пытается получать его **из A и B**, а не дожидается полного опустошения A. Золото не вставляется в занятый слот.

### Случай A2 — железо перестало реально поступать

A и B перестали отдавать железо; в слоте печи осталось 8 руды. Печь дорабатывает эти 8. При опустевшем слоте может
выбрать реально доступное золото из C; не ждёт нового железа просто потому, что оно видно в сундуке.

### Случай A3 — внешний Pull

Третья труба обращается к предметному OUTPUT справа. Ей доступен **только слот результата**, а не сырьё.

## Сценарий Б: Сборочный станок с тремя динамическими слотами

Рецепт A: железо ×2 + медь ×1 + уголь ×1. Рецепт Б: железо ×2 + олово ×1 + редстоун ×1.

- При выбранном рецепте Б входные маршруты принимают железо, олово, редстоун; не загружают медь/уголь.
- Предметы одного типа складываются в один занятый слот; заполнение его не даёт права занять второй свободный слот тем
  же типом (если рецепт не требует исключения).
- Выбор рецепта может исходить из GUI, чертежа или другого механизма.
- После запуска операции игрок меняет чертёж. Операция заканчивает предыдущий рецепт с собственными сохранёнными
  параметрами.
- Несовместимые остатки игрок сам забирает, если входные слоты доступны вручную.

## Сценарий В: Химический реактор (предмет + жидкость + газ)

**Вход:** металлический компонент + вода + кислород. **Выход:** предметный продукт + жидкостный побочный продукт + газ.

- В каждом жидкостном/газовом резервуаре не более одного типа ресурса.
- Все ингредиенты должны присутствовать полностью; затем они списываются атомарно.
- При 100% и полном газовом выходе **не выдаётся ни один** продукт. Прогресс остаётся 100%, FE более не расходуется.
- После освобождения газа весь набор выходит атомарно, затем операции можно продолжить.
- Если игрок меняет рецепт и во входном баке осталась вода, обычный OUTPUT **не раскрывает бак** внешнему насосу. Если
  есть SERVICE, выкачивание возможно через него. Если предусмотрено GUI-опустошение, удаляется **всё** содержимое, а не
  часть.

## Сценарий Г: Мультиблок без ручного доступа к хранилищу

После смены чертежа входные ресурсы стали несовместимы. Мультиблок пытается вернуть ненужные ресурсы через **первый
подходящий разрешённый выход** данного типа; если выход заполнен, проверяет следующие и удерживает остаток до
возможности передачи. Это инициированная машиной процедура возврата, **не разрешение** трубам выкачивать INPUT через
обычный OUTPUT.

## Сценарий Д: Четыре независимые камеры

- Общий вход: 10 железной руды. Каждая камера требует четыре. Первые две доступные по очереди запускаются, другие ждут;
  полный комплект списывается при старте, не по одному предмету.
- Камеры с различными рецептами: планировщик проверяет полный комплект каждого, а не одну общую «типовую руду».
- Сложной камере может понадобиться логическое резервирование — **необязательная** политика, которую машина вправе
  поддерживать.
- Общая FE: бюджет 40 FE/такт, четыре камеры по 20 FE за шаг; право на полный оплаченный шаг распределяется Round Robin.
- Раздельный/общий/смешанный выход: каждая операция выдаёт собственный **неделимый** набор; ожидание одной камеры не
  блокирует другую автоматически.

## Сценарий Е: Coal Generator Mk I (существующая база)

- 10 000 FE буфер; генерация 40 FE/t; общий вывод до 80 FE/t.
- BACK OUTPUT по умолчанию, LEFT/RIGHT/TOP/BOTTOM могут быть включены, FRONT без энергетического канала.
- FE Push от источника и Pull от внешнего кабеля делят один лимит; сохранение существующих тестов обязательно.
- Перевод гранных настроек на BlockEntity-порты — отдельный инкрементальный рефакторинг, а не переписывание всех
  энергокомпонентов одновременно.
