## Этап 1. База FE и идентичность портов — основная работа выполнена

- [x] Существуют `EnergyComponent` (буфер и операции хранения FE), `EnergyPortId`, режимы, политики, конфигурация и сериализатор. Исторический результат их восьми тестовых наборов — **125 тестов**; при дальнейших изменениях нужен актуальный полный прогон.
- [x] `EnergyDistributionManager` использует `EnergyPortId` вместо `Direction` во всех ключевых контрактах и состояниях.
- [x] Coal Generator Mk I сопоставляет собственные выходные стороны с устойчивыми `EnergyPortId`.
- [x] Проверены регрессии Pull/Push, ограничений FE/t и транзакций: **66/66 тестов** (`EnergyDistributionManagerTest` и `EnergyLifecycleRegressionTest`) после последних локальных оптимизаций.
- [x] Выполнена оптимизация расчётов спроса/резервов и снимков менеджера без изменения алгоритма; реальный benchmark перенесён на поздний этап.
- [ ] Перед объединением изменений с `main` сверить и перенести последнюю локальную версию менеджера, поскольку текущая ветка репозитория может содержать более раннюю реализацию.
- [ ] Добавить интеграционный сценарий **двух физических портов с одинаковым `Direction`** в будущем мультиблоке; это не повод заново менять математическую модель менеджера.

`TECH-DEBT-ENERGY-001` **закрыт в части менеджера**, но не равен готовности всех будущих физических портов и мультиблоков.

## На каждом этапе

- Сначала контракт и тесты на инварианты, затем производственный код.
- Сохранять работу Coal Generator Mk I и регрессию Push/Pull/fairness.

- Обновлять ADR при реальном изменении решения, а не при каждой внутренней оптимизации.
- Нагрузочное тестирование отложено по решению разработчика до более завершённого состояния мода.
