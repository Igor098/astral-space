# План внедрения после завершения архитектурного согласования

**Статус:** предлагаемый порядок, не разрешение немедленно писать production-код.

## Этап 0. Архитектурный аудит

- Сверить все 20 ADR с текущим исходным кодом.
- Для открытых вопросов зафиксировать решения только там, где это блокирует ближайший этап.
- Не создавать преждевременно `AbstractMachineBlockEntity`, `AbstractGeneratorBlockEntity` и подобные типы без выявленных общих задач.
- Сохранить уже действующие `ADR-ENERGY-001/002`.

## Этап 1. Проверка существующей FE-базы

- Запустить имеющиеся unit/integration tests (исторически 125 тестов по восьми энергокомпонентам).
- Описать и зафиксировать контракты `EnergyComponent`, `EnergyPortId`, режимов и политик.
- Написать сначала регрессионные тесты для смены `Direction` на `EnergyPortId` в `EnergyDistributionManager`, в том числе **два разных порта одной ориентации** и объединённый Push/Pull.
- Перенести только необходимые контракты, не переписывая рабочие лимиты/справедливость.

## Этап 2. Интеграция FE-конфигурации в Coal Generator Mk I

- Привязать пять доступных выходов к `EnergyPortConfiguration` в BlockEntity.
- Сохранять настройки портов через согласованный сериализатор; не поддерживать старые миры в качестве обязательной цели.
- `BlockState.OUTPUT_*` оставить как **производную визуальную проекцию** для существующей multipart-модели.
- Обновить server-side обработчик `ToggleCoalGeneratorOutputPayload`: не полагаться на клиентский бит/режим как авторитетный.
- Перевести `CoalGeneratorMenu`/`GuiSideConfigTab` на отдельную клиентскую проекцию состояния (возможно битовая маска для GUI, но не источник истины).
- Убрать старые `PortMode`, `SidePortConfig`, `SideConfiguration`, `CoalGeneratorEnergyOutputMapper` только после удаления всех зависимостей и регрессионной проверки.
- Сохранить лицевые состояния `CoalGeneratorFrontState`, базовые текстуры и поведение топлива.

## Этап 3. Предметная интеграция простого генератора и электропечи

- Отдельно определить внутренние группы слотов, их ограничения и внешние предметные маршруты.
- Для Coal Generator Mk I добавить безопасный вход предметного топлива через предметную capability, если это требуется игровому дизайну генератора.
- Для эталонной электропечи реализовать слот сырья и результата с независимыми гранями.
- Затем отдельно добавить АвтоВход/АвтоВыход с AS-MACHINE-005/006. Не смешивать всё в один большой рефакторинг.

## Этап 4. Производственные операции

- Определить контракт выбранного рецепта vs active operation.
- Атомарный запуск, пауза, сохранение прогресса, `WAITING_FOR_OUTPUT`, атомарный набор выдачи.
- Проверить сценарий смены рецепта при уже начатой операции.
- Многокомпонентные динамические слоты — следующим вертикальным срезом.

## Этап 5. Многокамерность

- Общие/индивидуальные/смешанные входы и выходы.
- Round Robin камер по полным наборам рецептов.
- Общий FE с полностью оплачиваемым рабочим тактом.
- Резервирование только для **реально нуждающегося** в нём механизма.

## Этап 6. Жидкости, затем газы

- Роли INPUT/OUTPUT/BIDIRECTIONAL, фиксированные/динамические баки.
- Смешанные рецепты и общая атомарность между типами.
- Для газов сначала отдельно определить resource API, допустимые объёмы/единицы, хранение, capability-совместимость и транспорт.

## Этап 7. Мультиблоки, SERVICE и возвраты

- Контроллер и физические хэтчи с логическими `portId`.
- Сервисный вывод входных ресурсов только через SERVICE.
- Автоматический возврат несовместимых ресурсов через первый подходящий производственный выход **без раскрытия INPUT-хранилища внешнему OUTPUT**.
- Опциональный явный полный сброс с серверным разрешением.

## На каждом этапе

- Сначала контракт и тесты на инварианты, затем production-реализация.
- Не жертвовать поведением Coal Generator Mk I ради новой абстракции.
- Не строить обходных слоёв ради совместимости с несуществующими старыми мирами.
- Обновлять ADR, когда решение реально меняется, а не только меняется код.
