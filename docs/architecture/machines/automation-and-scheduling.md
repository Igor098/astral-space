# Автоматизация и планирование

Связанные ADR: [003](decisions/AS-MACHINE-003.md), [005](decisions/AS-MACHINE-005.md), [006](decisions/AS-MACHINE-006.md), [010](decisions/AS-MACHINE-010.md), [011](decisions/AS-MACHINE-011.md), [019](decisions/AS-MACHINE-019.md).

## Не смешивать активное и пассивное подключение

- **Пассивный ITEM/FLUID/GAS INPUT:** внешняя труба сама помещает ресурсы в наши разрешённые хранилища.
- **АвтоВход:** наша машина периодически ищет соседний обработчик, пытаясь изъять допустимый ресурс.
- **Пассивный OUTPUT:** внешняя труба сама извлекает разрешённый результат.
- **АвтоВыход:** наша машина периодически пытается поместить результат во внешний обработчик.
- **Энергия:** производитель/накопитель отправляет через активный OUTPUT; отдельной GUI-опции АвтоВыход/АвтоВход для FE нет.
- **SERVICE:** извлечение инициирует внешнее сервисное устройство, не наша автоматика.

## Round Robin: три разных задачи

| Планировщик | Что чередует | Особенность |
|---|---|---|
| Выход предметов/жидкостей | **Начальный выходной маршрут** | Пропуск отказавшего соседа, общий лимит источника |
| Вход однослотовой машины | **Источники текущего типа предмета** | Тип удерживается, пока поступает; при прекращении подачи возможна смена |
| Камеры при общем запасе | **Попытку запустить полный рецепт** | Не резервирует ингредиенты по умолчанию |
| Камеры при общей FE | **Право на полностью оплаченный рабочий такт** | Камера либо расходует цену полного такта, либо не прогрессирует |

У одной машины могут сосуществовать несколько независимых планировщиков. Не нужно создавать общую очередь, в которой энергетические FE, слитки, газы и камеры конкурируют как будто это одинаковые единицы.

## Справедливость и бюджет

- Round Robin = отсутствие **фиксированного приоритета** первого направления/камеры, но не гарантия равных объёмов.
- Количество подключений не умножает установленный машиной общий лимит передачи.
- Лимиты соседей учитываются фактическими результатами операций.
- Реализация должна ограничивать число запросов и передач за один цикл.
- Если сосед отказал, это не даёт права уничтожить или зачислить ресурс.

## Ограничения источников

Если два сундука содержат железную руду, первый отдаёт максимум 2 предмета в цикл, второй — 3, а машина может принять 5, следует пытаться получить до 5 суммарно. Из-за заполнения внутреннего слота или собственного нулевого бюджета нельзя делать вывод об исчерпании внешнего ресурса.

## Резервирование для камер

В общей ресурсной группе некоторым машинам может потребоваться **логическое** резервирование части запаса, чтобы дорогая камера накопила полный комплект. Это **дополнительная политика конкретного механизма**, не встроенная в каждую машину. Зарезервированные предметы не списаны, но недоступны конкурирующим операциям. Снятие резерва не меняет фактическое количество.

## Возврат после смены рецепта — не обычный АвтоВыход

Для мультиблока без ручного доступа возврат несовместимого ингредиента использует **первый подходящий разрешённый выход** (AS-MACHINE-019), а не распределение Round Robin. Это **внутренняя операция возврата**, инициируемая контроллером, а не разрешение внешней трубе через обычный OUTPUT напрямую извлекать предмет из INPUT-хранилища. Для соблюдения AS-MACHINE-020 обычная внешняя OUTPUT capability по-прежнему предоставляет **только выходные хранилища**. Детальную передачу/промежуточный возвратный буфер проектируем отдельно.

## Производительность

- Не выполнять полный обход всех сторон каждый игровой такт, если машина не имеет ресурсов, разрешённых автодействий или потенциального прогресса.
- Для частых запросов соседних возможностей предусмотреть `BlockCapabilityCache` с валидностью и надлежащей инвалидацией (NeoForge 1.21.11).
- Не инициировать загрузку соседних чанков ради автоматизации.
- Избегать циклов перемещения предметов/жидкостей между соседними автосистемами; Round Robin **сам по себе** не является защитой от циклов.
- Не полагаться на то, что внешнее хранилище всегда имеет статический лимит/одинаковые результаты последовательных запросов.
