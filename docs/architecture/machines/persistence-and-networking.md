# Сохранение, синхронизация и серверная безопасность

**Статус:** общие последствия утверждённых ADR. Точные форматы данных и названия сетевых сообщений ещё не согласованы.

## Что необходимо сохранять

| Состояние | Почему |
|---|---|
| Содержимое внутренних слотов, баков, FE | Физическое владение ресурсами |
| Конфигурация разрешённых маршрутов | Настройки игрока должны сохраняться |
| Выбранный рецепт/источник выбора, если он имеет постоянное состояние | Продолжение выбранного производственного режима |
| Каждая начатая производственная операция | Смена рецепта и загрузка мира не отменяют производство |
| Прогресс и данные ожидающего неделимого набора | 100% + нет места для выдачи не должны превращаться в потерю продукции |
| Резервирование, если оно поддерживается и должно пережить сохранение | Иначе после загрузки другие камеры могут расходовать чужие резервы |

## Что необязательно сохранять

- Текущий индекс Round Robin для АвтоВыхода (AS-MACHINE-005): допустим новый старт после загрузки.
- Разовый кеш найденных соседей: пересоздаётся и валидируется.

## BlockState как визуальная проекция

Для `Coal Generator Mk I` текущие пять `OUTPUT_*`-флагов BlockState используются для отображения подключений. В будущем **источник истины — `EnergyPortConfiguration` в состоянии BlockEntity**, а BlockState только отражает нужные признаки для multipart-модели. Не позволять BlockState и NBT независимо менять один логический режим порта.

## Сетевое взаимодействие

- Клиентский экран показывает **проекцию** серверного состояния (режимы граней, содержимое, прогресс, ошибки обслуживания).
- Любое действие через GUI — запрос, а не авторитетное изменение: сервер проверяет расположение, доступность меню, право игрока, существование порта, допустимый режим, контекст машины и ресурсные ограничения.
- Изменение конфигурации или состояния, влияющее на доступность capability, требует корректной проверки уже выданных обработчиков и при необходимости инвалидации кэшей.
- `WAITING_FOR_OUTPUT` и прогресс 100% — состояние производства, которое может отображаться GUI, но оно **не принадлежит GUI**.

## Требования к атомарности

1. Вход: ни один расходуемый ингредиент не списан, пока нельзя согласованно списать **все** ресурсы и создать операцию.
2. Выход: нельзя выдать только часть набора продуктов операции.
3. Извлечение: получатель не может получить ресурс, который источник не списал, и наоборот.
4. Ошибка/отмена транзакции откатывает совместно изменённые ресурсные хранилища.
5. Сохранённое состояние не должно создавать второй экземпляр уже выданного продукта после повторной загрузки.

**Техническая пометка:** транзакционная атомарность в памяти и согласованность данных при неожиданном прерывании процесса — разные вопросы. Конкретную стратегию устойчивого сохранения зафиксированного набора/состояния надо проверить при проектировании реализации.

## Совместимость сохранений

**Миграции старых миров не требуются:** мод пока не опубликован и пользователь допускает создание нового мира. Это снимает обязанность сохранять устаревший формат `SideConfiguration`/старые флаги как схему вечной совместимости, но не снимает требования корректно сохранять и загружать данные в *новом* мире.
