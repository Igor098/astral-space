# AS-MACHINE-028 — Необязательное управление редстоуном через композицию

**Статус:** утверждено 2026-11-27 (9.12.A); компонент реализован и проверен локально разработчиком, интеграция в машины предстоит.  
**Область:** любые механизмы Astral Space, независимо от типа ресурса и наличия FE.  
**Связанные решения:** [023](AS-MACHINE-023.md), [025](AS-MACHINE-025.md), [026](AS-MACHINE-026.md), [027](AS-MACHINE-027.md).

## Контекст и решение

Управление редстоуном требуется генераторам, производственным машинам и потенциально насосам/накопителям, но не обязательно каждому механизму. Оно не является свойством FE-хранилища и не должно навязываться всем BlockEntity через наследование. Выбираем композицию: механизм, поддерживающий редстоун-контроль, владеет собственным `RedstoneControlComponent`; остальным компонент не нужен. Не вводим общий обязательный базовый класс, интерфейс или фабрику только ради редстоуна.

## Ответственность и Java-контракт

Пакет: `ru.greatdragonx.astralspace.common.machine`, рядом с существующим `RedstoneControlMode`. Enum не изменяется.

```java
public final class RedstoneControlComponent {
    private final Runnable onModeChanged;
    private RedstoneControlMode mode;

    public RedstoneControlComponent(@NonNull Runnable onModeChanged);
    public @NonNull RedstoneControlMode getMode();
    public boolean changeMode(@NonNull RedstoneControlMode mode);
    public boolean allowsOperation(boolean hasSignal);
    public void restoreMode(@NonNull RedstoneControlMode mode);
}
```

Сигнатуры выше — описание контракта, а не самостоятельный компилируемый Java-файл.

- Конструктор отклоняет null callback (`NullPointerException`), сохраняет его, устанавливает `IGNORE`, не уведомляет владельца. Отдельный параметр начального режима не вводится.
- `getMode()` возвращает ненулевой текущий режим без изменения состояния и уведомлений.
- `changeMode(mode)` сначала отклоняет null (`NullPointerException`); при том же режиме возвращает false без побочных эффектов. Иначе сохраняет новый режим, однократно вызывает `onModeChanged.run()` и при нормальном завершении возвращает true. Новый режим доступен внутри callback. Если callback выбрасывает исключение, оно распространяется вызывающему коду; режим автоматически не откатывается.
- `Runnable` достаточен, поскольку меняется одна настройка; владельцу не требуется идентификатор изменённого порта (в отличие от `EnergyPortConfiguration`). 
- `allowsOperation(hasSignal)` делегирует текущему enum, не хранит сигнал, не меняет режим и не вызывает callback.
- `restoreMode(mode)` отклоняет null и тихо устанавливает переданный режим, включая фактическое изменение; предназначен для восстановления до штатной работы.
- У каждого экземпляра независимое состояние; последовательное использование владельцем, без гарантий потокобезопасности. Нет зависимости от Level, BlockEntity, FE, топлива, рецептов, NBT или транзакций.

## Семантика сигнала

| Режим | Без сигнала | С сигналом |
|---|---|---|
| IGNORE | разрешено | разрешено |
| WHEN_POWERED | запрещено | разрешено |
| WHEN_UNPOWERED | разрешено | запрещено |

Разрешение редстоуна — только одно из условий операции, не гарантия её выполнения.

## Границы владельца

Владелец получает актуальный сигнал из мира, определяет допустимый серверный контекст, выбирает ограничиваемые операции, выполняет сохранение и синхронизацию. Компонент не определяет, что означает «работа» конкретного механизма. Обычная машина может читать сигнал около себя; источник сигнала для мультиблока зависит от конкретной конструкции и проверяется владельцем без навязывания общей топологии.

Генератор ограничивает редстоуном именно производство новой FE: при запрете не вызываются подготовка и завершение производственного тика, не списывается новое топливо и не уменьшается оплаченный цикл. Накопленная FE остаётся доступной для Push/Pull по живой портовой политике; редстоун не меняет доступность FE-портов, их режимы или общий исходящий бюджет. Редстоун не является обязанностью `AbstractEnergyMachineBlockEntity`, `GenerationProcess` и FE-контроллеров. `AbstractGeneratorBlockEntity` использует компонент через композицию. Точный публичный API генератора и защищённая точка получения сигнала согласуются в 9.12.A.8/9.16, не считаются реализованными.

Для потребителей и других механизмов конкретная рабочая операция определяет место проверки. Управление активной выдачей накопителя — возможный отдельный сценарий, а не обязательное правило этого ADR. Конструктивная готовность мультиблока не тождественна редстоун-разрешению.

## Сохранение и восстановление

Компонент не содержит serialize/deserialize и не определяет NBT-схему. Владелец читает и проверяет сохранённое имя режима, выбирает значение для отсутствующих/некорректных данных и вызывает тихое restoreMode, а не пользовательский changeMode. Для генераторов предложено единое имя ключа `redstone_control_mode` и fallback IGNORE; окончательная структура NBT утверждается в 9.15. Сигнал и вычисленное разрешение не являются настройкой компонента.

[test-matrix.md](../test-matrix.md). Публикация Java-кода, миграция Coal/Lava и проверка интеграции выполняются отдельно.
