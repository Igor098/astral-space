# AS-MACHINE-020 — SERVICE как отдельный маршрут доступа к входным ресурсам

**Статус:** утверждено  
**Область:** архитектура машин Astral Space  
**Последнее согласование:** 2026-11-08  
**Связанные решения:** [Реестр ADR](../README.md#реестр-решений)


## Решение
- `SERVICE` — **самостоятельный логический маршрут** для извлечения ресурсов из явно разрешённых **входных** хранилищ.
- Обычный `INPUT` допускает подачу ингредиентов; обычный `OUTPUT` обращается только к выходным хранилищам и **никогда не используется для извлечения входных ресурсов**.
- Сервисный маршрут допускается только у механизмов, которые его поддерживают; размещение разрешается на выбранных конструкцией гранях.
- При сервисном извлечении ресурсы **передаются**, а не уничтожаются. Извлечение инициирует внешний насос/устройство, обычного АвтоВыхода для `SERVICE` нет.
- Сервисный доступ подчиняется ограничениям передачи, учёту резервирования и безопасности уже активных операций.
- Стандартная NeoForge capability для жидкости/предметов может представлять сервисный доступ к выбранному входному хранилищу, но смысл `SERVICE` задают **правила маршрутизации**, а не новый вид ресурса.
- `SERVICE` **взаимоисключает** `INPUT` и `OUTPUT` того же типа ресурса на одной грани. Обычный OUTPUT по-прежнему не извлекает содержимое входного хранилища.

## Границы
- Совмещение `INPUT + SERVICE` одного типа на одной грани запрещено. Выбор обслуживаемой группы при нескольких входных резервуарах остаётся открытым вопросом.
- Сервисное извлечение не является кнопкой принудительного удаления по [AS-MACHINE-019](AS-MACHINE-019.md).
