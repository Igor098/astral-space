# Предметы: слоты, маршруты и политика загрузки

ADR: [002](decisions/AS-MACHINE-002.md), [004](decisions/AS-MACHINE-004.md), [006](decisions/AS-MACHINE-006.md), [007](decisions/AS-MACHINE-007.md), [020](decisions/AS-MACHINE-020.md).

## Базовая электропечь

```text
Слот 0 — INPUT:  автоматическая вставка допустимого сырья
Слот 1 — OUTPUT: автоматическое извлечение результата
```

Обычные внешние устройства **не вставляют** предметы в слот результата и **не извлекают** содержимое входного слота через OUTPUT. Ручное управление из GUI — отдельная политика.

Несколько граней входа могут вести в слот 0; несколько граней выхода — брать из слота 1. Вся машина использует **единственный фактический запас** в каждом слоте.

## Строгая идентичность предмета

Для «того же самого ресурса» учитываем предмет и значимые компоненты, **не количество** в стеке. Железная и глубинная железная руда — разные ресурсы даже при одинаковом результате переплавки. Совпадение тега или совместимость с рецептом не заменяет строгого равенства.

## Однослотовая политика (AS-MACHINE-006)

1. Первым успешным поступлением определяется активный тип предмета.
2. С каждого активного АвтоВхода пытаемся получить именно его.
3. Порядок начальных источников чередуется, объёмы ограничены конкретными источниками и бюджетом машины.
4. Если из всех доступных внешних источников этот тип перестал реально поступать, **не ждём его из-за одного лишь видимого наличия в сундуке**.
5. Уже загруженный тип дорабатывается. Как только слот опустел, разрешён выбор другого фактически доступного типа.
6. Не трактуем заполнение нашего слота или нулевой собственный лимит приёма как доказательство отсутствия ресурса во внешних источниках.

Пассивная внешняя вставка должна соблюдать текущие ограничения выбора типа; нельзя обойти приоритет сторонней трубой.

## Многокомпонентные рецепты

Внутренняя входная группа может динамически распределять *разные* ингредиенты. Один и тот же тип в двух слотах допускается только по явному требованию рецепта/конструкции, даже если первый слот уже заполнен. Все способы подачи — АвтоВход, внешние ITEM INPUT — используют те же инварианты.

Не назначаем всем машинам один обязательный способ выбора рецепта: конкретный механизм может получать выбор из GUI, чертежа или другой системы.

## Пример блокировки без защиты

Три свободных слота, рецепты `(железо, медь, уголь)` и `(железо, олово, редстоун)`. Если слоты заняты железом, медью и оловом, ни один рецепт не завершить. Поэтому при явно выбранном рецепте загрузка ориентируется на **его** ингредиенты. Для автоматического выбора нужна отдельная политика предотвращения блокировки — в открытых вопросах.

## Возврат несовместимых предметов

При смене рецепта станок с доступным GUI хранит несовместимые предметы до действий игрока. Мультиблок без ручного доступа отправляет их по первому подходящему выходу соответствующего типа, остаток сохраняет. Входные предметы нельзя извлекать через обычный OUTPUT; опциональный SERVICE описан в AS-MACHINE-020.

## Предварительные проверки

- Проверять допустимость предмета до фактического внешнего извлечения.
- Списывать расходуемые ингредиенты только при атомарном запуске операции.
- Не путать свободный слот инвентаря с разрешением принять любой предмет.
