# Открытые вопросы — не считать утверждёнными

Все перечисленные ниже пункты **не были окончательно согласованы**. Не реализовывать «по умолчанию» как будто это ADR.

## Порты и интеграция

1. Унифицированная модель идентификаторов предметных/жидкостных/газовых портов; привязка к хэтчам мультиблоков.
2. Как выбирать конкретную входную группу при нескольких `SERVICE`-целях без обязательного выделенного хэтча на каждую.
3. Совмещение `SERVICE + INPUT` одного ресурса на грани; `SERVICE + OUTPUT` того же типа **пока запрещено** AS-MACHINE-020.
4. Физическое размещение нескольких внешних кабелей/труб у одной грани и внутриигровая визуализация.
5. Правила фильтров для нескольких логических INPUT/OUTPUT маршрутов одного ресурса на грани.
6. Может ли игрок выбирать маршрутизацию по именованным группам для сложных машин и в каком GUI.
7. Будет ли конфигурация выходного направления для энергии отличаться для иных классов генераторов/накопителей.

## Автоматизация

8. Интервал, лимиты и бюджет запросов АвтоВхода/АвтоВыхода для разных машин.
9. Точная очередь распределителя: курсор маршрута, количество обходов за один цикл, квант, отдельный кредит справедливости.
10. Реакция на непрерывную внешнюю подачу (пассивный Push), когда однослотовая машина освобождает свой слот и активный предмет больше не вытягивается локальным АвтоВходом.
11. Как определять доступность ресурса, если внешний обработчик не даёт чётких гарантий наблюдаемого содержимого или ограничен транзакциями.
12. Защита от циклов `АвтоВыход -> АвтоВход -> ...` в конкретных транспортных схемах.
13. Порядок выбора следующего ресурса, если несколько типов стали доступны одновременно и не был выбран активный тип.

## Рецепты, производство, камеры

14. Конкретные варианты выбора рецепта для определённых машин и правила автоматического выбора без блокировки несовместимыми остатками.
15. Что делать при изменении/удалении описания рецепта в дата-паке во время сохранённой операции: операция хранит snapshot достаточных данных, но формат ещё не выбран.
16. Рецепты с разными альтернативами по тегам и с предметами с компонентами; случайные выходы и момент фиксации результата.
17. Нерасходуемые катализаторы/инструменты с износом — проверка и атомарность урона.
18. Конкретные правила возврата резерва при конфликтующих камерах; timeout, deadlock, fairness.
19. Порядок конкурирующей выдачи нескольких готовых операций в общий выходной буфер.
20. Что происходит с активной операцией при физическом уничтожении машины/разборке мультиблока (не равно смене рецепта).

## Жидкости и газы

21. Собственные газовые идентификаторы, единицы количества, API внешнего подключения, совместимость с другими модами.
22. Газовые баллоны/хэтчи, давление, температура, возможные смеси — отдельный будущий дизайн.
23. Правила частичной передачи у сервисного насоса, лимиты объёма и их сопоставление с лимитами автоматики.
24. Разрешение игроку создавать жидкости/газы как выходы комбинированного рецепта в группах баков при неравных вместимостях.

## Persistence / UI

25. Точные схемы NBT/кодеков операции и различных групп хранилищ; версия сохранения новой структуры.
26. Обновление клиентской проекции при быстром изменении конфигурации/автоматизации и правила правообладания меню.
27. Формы визуального отображения SERVICE, полных сбросов и состояния 100% ожидания.

## Отдельный технологический долг

- Сменить идентичность в `EnergyDistributionManager` с `Direction` на `EnergyPortId` **с регрессионными тестами**, не переделывая рабочий Push/Pull наугад.

## Правило ведения реестра

Когда вопрос решён, создать новый ADR либо явно обновить действующий с пометкой причины/даты. Не удалять открытый вопрос без фиксации разрешения.
