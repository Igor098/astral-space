# Жидкостная подсистема

ADR: [003](decisions/AS-MACHINE-003.md), [005](decisions/AS-MACHINE-005.md), [013](decisions/AS-MACHINE-013.md), [017](decisions/AS-MACHINE-017.md), [018](decisions/AS-MACHINE-018.md), [019](decisions/AS-MACHINE-019.md), [020](decisions/AS-MACHINE-020.md).

## Хранилища

- Один резервуар содержит **один тип жидкости** одновременно; самопроизвольное смешивание не допускается.
- Машина может задавать **фиксированную роль/содержимое** резервуара или **динамическое назначение** на основе первого допустимого поступления.
- В динамической группе один тип жидкости не растекается по всем свободным бакам, если только конструкция или рецепт не требуют обратного.
- После полного опустошения динамический бак может принять другой допустимый тип.
- Несколько входных граней могут наполнять один бак; множество активных выходов используют Round Robin.

## Роли баков

- `INPUT` — ингредиенты производства; обычный OUTPUT не извлекает его содержимое.
- `OUTPUT` — результаты; обычная внешняя закачка запрещена.
- `BIDIRECTIONAL` — допустим только там, где это осознанно поддерживает машина.

Роль резервуара не равна конфигурации грани. Два маршрута на одной грани могут обращаться к разным внутренним бакам.

## Рецепты

Вода/другие жидкости могут потребляться вместе с предметами и газами; единая транзакция запуска. Жидкостные результаты входят в **неделимый набор** всей продукции и должны помещаться атомарно вместе с предметами и газами.

## Смена рецепта и обслуживание

Несовместимая жидкость сохраняется до ручного извлечения или возврата в подходящий выход мультиблока. Если предусмотрен **SERVICE**, насос может выкачать нужное количество из входного бака. Обычный OUTPUT этого не позволяет. В некоторых механизмах игрок может выполнить **полный** принудительный сброс — без «удалить половину».
